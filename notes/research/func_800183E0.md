## Corrected defects in the inherited attempt

These are source reconstruction corrections, not allocation tweaks:

1. **Initialize the drawing y value on every main-body path.** Target
   `0x800186E4` stores the incoming y at stack offset 0x1C before the
   `D_8005E474` split. The old source initialized `sp1C` only in the else
   arm, then used it on other paths. The corrected assignment follows
   `func_8001A19C()` before the split.
2. **Use halfword units for pointer advances.** Target `0x80018884` and
   `0x8001888C` add two bytes; `0x800188A4` adds four. The old `u16 *`
   source incorrectly used `ptr + 2`, `buf1 + 2`, `buf1 + 4`. Corrected:
   `ptr + 1`, `buf1 + 1`, `buf1 + 2`.
3. **Preserve the scan's postincrement.** Target `0x80018974..0x80018984`
   loads through the current pointer, increments in the branch delay slot,
   then decrements after finding the sentinel. The corrected inner scan is
   `while (*cur++ != 0xFFFE) { }`, followed by `cur--` and the outer step.
   The inherited pretest loop ended one halfword earlier. The fresh raw m2c
   draft also used a different preincrement form; do not trust it over the
   original load/delay-slot semantics.
4. **Selection storage is unsigned.** Target `0x800186A8` loads
   `D_8005E4A4` with `lhu`; the attempt's tentative definition is now `u16`
   instead of `s16`, with no pointer reinterpretation needed for the callee.
5. **Restore `addPrim` boundaries** for the two draw-area packets.

Correcting a real defect sometimes worsened the staged key: initializing y
changed a join and produced a degraded CFG comparison under baseline flags.
The old lower population number is not a reason to restore undefined state.

## Bounded source experiments, not impossibility claims

Baseline source variants tested SDK macros, the semantic corrections above,
shared scan pointer, reuse of the earlier `f4` variable as the loop counter,
narrow status locals, narrow/split coordinates, and factored common-tail
calculations. Neither pointer reuse nor that one counter reuse removed the
baseline mismatch. These are individual shapes, **not** an exhaustive
counter-reuse grammar or proof that baseline clean C is impossible.
A mechanically repaired m2c-type alternative (`faithful-types.c`) was worse;
it was not promoted.

Under experimental `-fno-gcse`:

- splitting the step and y-coordinate variables produced `[0,51,18,22]`,
  worse than the primary's `[0,42,12,24]`;
- writing the return-status mask as `s3 & 0xFFFF` instead of `(u16)s3`
  emitted identical words;
- reusing `s3` as the outer scan's 0xFFFE sentinel **after capturing the
  return status** produced `[0,42,10,24]`, **355/466**. This is the source
  preserved in the disabled block. It clears the staged block-0 residual
  but introduces an allocation difference in block 64; it does not resolve
  the population problem.
